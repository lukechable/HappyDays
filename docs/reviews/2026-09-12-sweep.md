# Bug, security and performance sweep — 12 September 2026

This release includes the requested Gmail buckets/collapsible sidebar, corrected Cliniko payment information and bank-transfer investigation filters, plus removal of inactive Cliniko users and the unwanted Practice/Business hours controls from Settings. Custom checkout overrides and booking creation APIs are removed: `/book` and legacy booking URLs open Cliniko’s own booking/payment page. Existing payment receipts remain accessible. Confirmed sweep fixes follow.

| Public settings queries enumerated internal values, including guest signing material and OAuth state; public mutation accepted internal keys | Explicit preference allowlist on reads/writes; validation; indexed reads. Guest signing keys rotate to version 2 when first used, with atomic installation | Authenticated/anonymous access tests, concurrent key installation |

Validation: full automated tests, TypeScript checks for frontend and Convex, ESLint, production webpack build, dependency audit, patch whitespace check, and deployed route/health checks. External financial writes, real patient bookings, outbound email and Tyro claims are not exercised during verification. The existing Railway **staging** service is the deployment target; no separate production service is configured.

Security boundaries: staff share practice data intentionally. File URLs already obtained cannot retract a downloaded copy. Existing PDF exports are not retroactively sanitized. Guest key rotation may require guest testers to sign in again. The review is an application code/dependency sweep, not an independent penetration test.

Dependency references: [PDF.js advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j), [official SheetJS installation](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/), [Sentry advisory](https://github.com/advisories/GHSA-593m-55hh-j8gv). The SheetJS tarball is pinned in the lockfile with integrity verification because npm's `xlsx` package remains outdated.

Gmail quota reference: [Google's current usage limits](https://developers.google.com/workspace/gmail/api/reference/quota). The shared limiter conservatively targets 80 units/second with a bounded burst against the current 6,000 units/minute default, leaving room for ancillary requests.
