# App wiring sweep — 13 September 2026

Reviewed the 21 staff page routes, their navigation entries, tabs, summary cards, table actions and cross-module destinations, plus public booking, download, signature and authentication routes. The route regression checks literal links and parameterised path links against real Next.js pages/handlers; computed destinations also received source review.

| Area | Corrections |
| --- | --- |
| Dashboard / overdue mail | Badge, dashboard preview, mailbox membership and thread pills share one overdue predicate. Snoozed, replied and automatically answered threads are treated consistently. Dashboard reads indexed headers directly instead of treating Gmail fetch failures as an empty list. Other-mailbox records are explicitly counted and explained. |
| Mail navigation | Overdue, assigned and matter views paginate all matching records instead of filtering a truncated first batch. Opening a thread preserves its folder in the header and active navigation. Mobile folder selector exposes navigation hidden with the desktop sidebar. Keyboard selection works in mail search and address suggestions. |
| Tasks | Today/week/overdue use Melbourne calendar dates. All-day tasks do not become overdue at midnight at the start of their due date. Badge matches All open. Completed toggle fetches completed records. Matter links filter tasks and quick-add carries that matter. Task details can link/unlink matters. Calendar dragging changes the due date without clearing notes, assignee, list or recurrence. Mobile task/list selector and invalid view defaults added. |
| Invoices / payments | Summary cards open matching invoice/status filters. Invoice flags exclude unlinked/closed matters from report alerts and exclude void/draft invoices from debt alerts. All mirrored invoice/payment records are used consistently instead of different 100/300/500-record windows. Paid report alert agrees with navigation badge. Selecting Delivered records delivery; selecting Report due removes delivery evidence. |
| Transactions | Type, period and search are URL filters; monthly totals and rows use Melbourne month boundaries. Bank export and received total use the visible bank rows. Invoice candidates open the specific invoice search and are labelled unconfirmed. |
| Matters | Counts derive from current thread/file/task relationships rather than stale duplicate links. Counts link to scoped destination pages. File rows open actual file detail routes. Delivery entries link to scoped download codes and signature requests. Deleting a matter unlinks remaining dependent records. |
| Files / reports | Matter filters survive tabs and search. Download-code links filter by file; Sent and signature requests can filter by matter. File matter unlink uses explicit null. Sent Gmail links map into the viewing user's mailbox. Uploads verify the response and report the actual success count. Report summary cards open their corresponding filters. |
| Court | Open, upcoming, overdue and completed cards/tabs share URL filters and row predicates. |
| Cliniko | Patient search works by keyboard. Referral case dialog's Create button submits the form. Settings links use actual tabs rather than nonexistent hash anchors. Appointment types and native Cliniko booking destinations remain connected. |
| PDF / shell | Mail's Sign action opens the markup tab. Switching source PDFs cancels obsolete reads and resets the document; load/save failures are visible. Invalid/non-PDF sources have actionable states. Signature request action accurately describes opening an email draft. Destinationless notifications no longer jump to Dashboard; navigation closes the popover. Stale/invalid deep links have retry/dashboard recovery. |

Validation: typecheck, ESLint, 74 automated tests (65 Vitest plus 9 rebate rules), production webpack build with all routes generated. Regression fixtures cover >100 excluded overdue records, multiple mailboxes and pagination, task preservation, matter unlink/deletion, invoice flags and valid route destinations. Existing mail deletion, security, booking and rebate tests remain passing.

Live verification is read-only. No emails, payments, claims, patient changes or public document redemptions are used as smoke tests. Medicare processing remains subject to the existing fixed launch cutoff and Tyro credential guards; this sweep does not activate it.
